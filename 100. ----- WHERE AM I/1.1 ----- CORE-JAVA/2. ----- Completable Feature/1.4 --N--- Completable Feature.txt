CompletableFuture - Simple Explanation

Step 1: What is CompletableFuture?

	CompletableFuture allows a task to run asynchronously (in the background) without blocking the current thread.

	Simple Definition:
	"CompletableFuture lets a task execute in the background and notifies the caller when it is completed."

Step 2: Why do we use CompletableFuture?

	We use it for two purposes:

	Internal Purpose (Inside the Application)
	External Purpose (For the Caller/Client)
	
Step 3: Internal Purpose

	This is about how the application works internally.

	Benefits
	✅ Non-blocking execution
	✅ Background processing
	✅ Parallel execution
	
	✅ Better resource utilization
	✅ Better scalability	
	
Interview Answer

	"We use CompletableFuture internally so that long-running operations don't block the request thread."	
	
Step 4: External Purpose

	This is about what the client/user gets.

	Benefits
	✅ Faster response
	✅ Non-blocking API
	✅ Can continue other work
	✅ Supports callbacks
	✅ Easy to chain multiple async operations	
	
Interview Answer

	"The caller doesn't have to wait. They can continue their work and process the result once the operation is complete."
	
Step 5: Internal vs External

| Internal Purpose             | External Purpose            |
| ---------------------------- | --------------------------- |
| Runs in background           | Non-blocking API            |
| Better scalability           | Faster user experience      |
| Uses thread pool/executor    | Caller can continue working |
| Doesn't block request thread | Supports callbacks/chaining |


Step 6: Real-Time Example
	Food Delivery App

	Without CompletableFuture

		Place Order

		Wait 5 Seconds

		Order Confirmed
		
	The user waits until everything finishes.	
		
Step 7: Best Interview Answer

	"CompletableFuture serves both internal and external purposes. Internally, it enables asynchronous, non-blocking processing using background threads, improving scalability and resource utilization. Externally, it provides a non-blocking API so callers can continue their work and handle the result when it becomes available."

1. thenApply() - Transform the Result

	You can chain thenApply() multiple times. Each thenApply() receives the result of the previous stage, transforms it, and passes it to the next stage.

																.thenApply(id -> "Employee-" + id)

																// 2nd thenApply
																.thenApply(name -> name.toUpperCase());

														// Get the final result
														String result = future.join();

														// Use the result
														System.out.println(result);
														System.out.println("Length : " + result.length());

		String result = CompletableFuture
						.supplyAsync(() -> 100)  //supplyAsync() → Produces the initial value.

						.thenApply(num -> num + 50)   // 150 //Every thenApply() → Takes the previous result and returns a new result.

						.thenApply(num -> num * 2)           // 300

						.thenApply(num -> "Final Value: " + num)

						.join();//join() → Waits for the computation to finish and retrieves the final result.

2. thenCompose()	thenCompose() is used when the second asynchronous task depends on the result of the first asynchronous task.

		The important point is:

		thenApply() returns a normal value.
		thenCompose() returns another CompletableFuture.
		
		  CompletableFuture<String> future = CompletableFuture
                .supplyAsync(() -> 101)

                .thenCompose(id ->
                        CompletableFuture.supplyAsync(() -> "Employee-" + id))

                .thenCompose(name ->
                        CompletableFuture.supplyAsync(() -> name + " works in Java Team"));

        String result = future.join();

        System.out.println(result);

				Use thenCompose() when each async operation depends on the previous async result.

				Real-world examples:

				Login → Fetch User → Fetch Permissions
				Employee ID → Employee Details → Salary Details
				Order ID → Order Details → Invoice
				Customer ID → Account Details → Transaction History

3. thenCombine()	Merge independent futures

		thenCombine() is used when two asynchronous tasks are independent, and after both complete, you combine their results.

		Rule: Both tasks can run at the same time because they do not depend on each other.
		
		Example 1: Employee Name + Department

			Suppose:

			Task 1 fetches the employee name.
			Task 2 fetches the employee department.
			After both finish, combine them.
		
		CompletableFuture<String> employeeName =CompletableFuture.supplyAsync(() -> "Sunil");

        CompletableFuture<String> department =CompletableFuture.supplyAsync(() -> "Java Team");

        CompletableFuture<String> result =employeeName.thenCombine(department,
                        (name, dept) -> name + " works in " + dept);

        System.out.println(result.join());
		
		
		Example 2: Product Price + Discount

			Suppose:

			Task 1 gets the product price.
			Task 2 gets the discount.
			After both complete, calculate the final price.

Difference between thenCompose() and thenCombine()
			
| `thenCompose()`                                     | `thenCombine()`                                |
| --------------------------------------------------- | ---------------------------------------------- |
| Second task **depends** on the first task's result. | Both tasks are **independent**.                |
| Runs tasks one after another.                       | Both tasks can run in parallel.                |
| Example: Employee ID → Employee Details             | Example: Employee Name + Department            |
| Returns a flattened `CompletableFuture<T>`.         | Combines the results of two completed futures. |
			
Easy way to remember
	thenCompose() = Dependency (Task 2 needs Task 1's result)
	thenCombine() = Parallel + Merge (Task 1 and Task 2 are independent, then merge their results)

allOf()			Wait for all futures

		CompletableFuture.allOf() is used when you have multiple independent asynchronous tasks and you want to wait until all of them complete.

		Important: allOf() does not combine results automatically. It only waits for all tasks to finish. You must call join() on each future to get its result.
		
		Example 1: Fetch Employee Name, Department, and Salary

			Suppose we need to fetch:

				Employee Name
				Department
				Salary

				These are independent tasks, so they can run in parallel.
			
															CompletableFuture<String> name =
																	CompletableFuture.supplyAsync(() -> "Sunil");

															CompletableFuture<String> department =
																	CompletableFuture.supplyAsync(() -> "Java Team");

															CompletableFuture<Integer> salary =
																	CompletableFuture.supplyAsync(() -> 80000);

															// Wait for all tasks
															CompletableFuture<Void> all =
																	CompletableFuture.allOf(name, department, salary);

															// Wait until all complete
															all.join();

															// Read individual results
															System.out.println("Name       : " + name.join());
															System.out.println("Department : " + department.join());
															System.out.println("Salary     : " + salary.join());	
			
			
										
								When should you use allOf()?

									Use allOf() when:

									You have 3 or more independent async tasks.
									You need all tasks to complete before continuing.
									You don't want to manually call join() one by one just to wait.

									Examples:

									Fetch User, Orders, and Notifications together.
									Download multiple files.
									Call multiple microservices in parallel.
									Generate multiple reports simultaneously.		
			
Difference between thenCombine() and allOf()		
				
	| `thenCombine()`                       | `allOf()`                                     |
	| ------------------------------------- | --------------------------------------------- |
	| Combines **2** futures.               | Waits for **any number** of futures.          |
	| Returns the combined result directly. | Returns `CompletableFuture<Void>`.            |
	| Used to merge two results.            | Used to wait for all tasks to finish.         |
	| Example: Name + Department            | Example: Name + Department + Salary + Address |
		
Interview Tip

	Think of it like this:

	thenCombine() → 2 tasks → Combine their results.
	allOf() → Many tasks → Wait for all of them to finish.

exceptionally()	Fallback on error

		exceptionally() is used to handle exceptions in a CompletableFuture pipeline and provide a fallback value instead of letting the program fail.

		Rule: If any previous stage throws an exception, exceptionally() is executed.

		CompletableFuture<Integer> future = CompletableFuture
						.supplyAsync(() -> 10 / 0)   // Exception

						.exceptionally(ex -> {
							System.out.println("Error: " + ex.getMessage());
							return 0;   // Default value
						});

				System.out.println("Result: " + future.join());
	Ex: 2
				
			CompletableFuture<String> future = CompletableFuture
							.supplyAsync(() -> {

								int employeeId = 999;

								if (employeeId != 101) {
									throw new RuntimeException("Employee Not Found");
								}

								return "Sunil";
							})

							.exceptionally(ex -> {
								System.out.println("Error: " + ex.getMessage());
								return "Unknown Employee";
							});

			System.out.println(future.join());

Real-Time Use Cases

1. Microservice Call: CompletableFuture.supplyAsync(() -> callPaymentService())
									   .exceptionally(ex -> "Payment Service Unavailable");
									   
				Instead of crashing, return a friendly message.

2. Database Query; CompletableFuture.supplyAsync(() -> getEmployee())
									.exceptionally(ex -> new Employee("Default Employee"));


				Return a default employee if the database is unavailable.


Without exceptionally()

When should you use exceptionally()?

		Use it when you want to:

			Return a default value if an async task fails.
			Log the exception and continue processing.
			Prevent the entire async pipeline from failing.

		Examples:

			Payment service unavailable → Return "Payment Pending".
			Employee not found → Return a default employee.
			File download fails → Return "Download Failed".
			Database unavailable → Return cached data.

exceptionally() vs thenApply()

| `thenApply()`                          | `exceptionally()`                                      |
| -------------------------------------- | ------------------------------------------------------ |
| Runs when the previous stage succeeds. | Runs only when the previous stage throws an exception. |
| Transforms a successful result.        | Handles failures and provides a fallback result.       |
| Example: `100 → 200`                   | Example: Exception → `0`                               |

Easy interview answer:

		thenApply() → Process success.
		exceptionally() → Handle failure and return a fallback value.


handle()		Process success or error


		handle() is one of the most powerful methods in CompletableFuture.

		Unlike exceptionally():

		✅ handle() is called whether the previous stage succeeds or fails.
		✅ It receives both the result and the exception.
		✅ It always returns a new value.

		handle((result, exception) -> {
			...
		})

		result → Contains the successful result (or null if an exception occurred).
		exception → Contains the exception (or null if the computation succeeded)

		CompletableFuture<String> future = CompletableFuture
						.supplyAsync(() -> 50000)

						.handle((salary, ex) -> {

							if (ex == null) {
								return "Salary : " + salary;
							} else {
								return "Salary not available";
							}
						});

				System.out.println(future.join()); //Salary : 50000
																
														
														CompletableFuture<String> future = CompletableFuture
																.supplyAsync(() -> {

																	throw new RuntimeException("Employee Not Found");

																})

																.handle((result, ex) -> {

																	if (ex != null) {
																		return "Default Employee";
																	}

																	return result;
																});

														System.out.println(future.join());  // output: Default Employee
														
	Difference between handle() and exceptionally()
	
		exceptionally()

		Runs only on failure.													
																
		CompletableFuture<Integer> future =
				CompletableFuture.supplyAsync(() -> 10 / 0)
						.exceptionally(ex -> 0);														
																	
			handle()

			Runs on both success and failure.	

			CompletableFuture<Integer> future =
					CompletableFuture.supplyAsync(() -> 100)

					.handle((result, ex) -> {

						if (ex != null)
							return 0;

						return result * 2;
					});

			System.out.println(future.join());

If an exception occurred instead, the same handle() block would run and could return 0.

| Method            | Success | Failure | Access Result | Access Exception |
| ----------------- | :-----: | :-----: | :-----------: | :--------------: |
| `thenApply()`     |    ✅    |    ❌    |       ✅       |         ❌        |
| `exceptionally()` |    ❌    |    ✅    |       ❌       |         ✅        |
| `handle()`        |    ✅    |    ✅    |       ✅       |         ✅        |

When should you use handle()?

Use handle() when you want to:

	Process the successful result if everything is fine.
	Recover from an exception if something goes wrong.
	Continue the pipeline with a value regardless of success or failure.
Common real-world scenarios
	Payment service → Return payment status if successful, otherwise "Payment Pending".
	Employee service → Return employee details if found, otherwise "Default Employee".
	File processing → Return processed content if successful, otherwise "Empty File".
	Database query → Return data if available, otherwise return cached/default data.

Easy interview answer
	thenApply() → Runs only on success.
	exceptionally() → Runs only on failure.
	handle() → Runs in both success and failure cases, giving you access to both the result and the exception.

whenComplete() is mainly used for logging, cleanup, auditing, or notification after a CompletableFuture completes.

	Rule: whenComplete() is executed whether the task succeeds or fails.

	Unlike handle():

	✅ It receives both the result and the exception.
	❌ It does not change the result.
	❌ It is not meant for recovery.

whenComplete((result, exception) -> {
    ...
})

result → Success result (or null if failed)
exception → Exception (or null if success)

example:

				import java.util.concurrent.CompletableFuture;

				public class WhenCompleteExample1 {

					public static void main(String[] args) {

						CompletableFuture<String> future = CompletableFuture
								.supplyAsync(() -> "Sunil")

								.whenComplete((result, ex) -> {

									if (ex == null) {
										System.out.println("Successfully fetched: " + result);
									} else {
										System.out.println("Error: " + ex.getMessage());
									}
								});

						System.out.println("Final Result: " + future.join());
					}
				}
Successfully fetched: Sunil
Final Result: Sunil

When should you use whenComplete()?

Use it for:

	Logging
	Audit records
	Closing resources
	Sending notifications
	Measuring execution time
	Printing success/failure status

Examples:

	Log "Payment Successful".
	Log "Employee fetched".
	Record API response time.
	Close database connections.
	Send an audit event after processing.

Easy Interview Answer
handle() → Inspect the result/exception and return a new value (it can recover).
whenComplete() → Inspect the result/exception for side effects only (logging, cleanup, auditing). It does not change the result or recover from exceptions.
		
	Why do we need it? Future
	-------------------------
	
		Before Java 8, we used Future.

			Problem with Future:

				Cannot chain tasks
				No easy exception handling
				Blocking using .get()

			CompletableFuture solves all these problems.
			
			Important Methods of Future
			Method			Purpose
			
			get()			Wait and get result (blocking)
			cancel()		Cancel task
			isDone()		Check if completed
			isCancelled()	Check if cancelled
						
			Major Problems with Future 

				❌ get() is blocking

				❌ Cannot chain tasks

				❌ No easy exception handling

				❌ Cannot combine multiple futures easily

				❌ No callback support
			
	Note: If we call get() or join() on CompletableFuture, the current thread becomes blocking until the result is available.

		get: checked exception
		join: unchecked exception

------------------------------------------Already we have Thread and WebClient then why do we use Completable Feature

That's an excellent interview question. The answer is that **`CompletableFuture` is not a replacement for `Thread` or `WebClient`; it is an abstraction for managing asynchronous work.** It makes writing, combining, and handling async operations much easier.

Let's compare them.

---

# Can we use Thread?

**Yes.**

```java
new Thread(() -> {
    // Long running task
}).start();
```

### Problems

* ❌ Creates a new thread every time (expensive).
* ❌ Hard to get the result back.
* ❌ No easy way to chain operations.
* ❌ No built-in exception handling.
* ❌ Difficult to combine multiple tasks.

---

# Can we use WebClient?

**Yes.**

`WebClient` is already **non-blocking**.

```java
webClient.get()
         .retrieve()
         .bodyToMono(Employee.class);
```

### But...

`WebClient` only solves **HTTP communication**.

It doesn't help you:

* Run database queries asynchronously.
* Execute CPU-intensive calculations.
* Combine multiple asynchronous tasks.
* Handle async exceptions in a clean way.

---

# Why use CompletableFuture?

Because it provides **a complete framework for asynchronous programming**, regardless of whether the task is:

* Calling a REST API
* Querying a database
* Reading a file
* Performing calculations
* Running multiple tasks in parallel

---

# Example 1: Thread vs CompletableFuture

### Using Thread

```java
Thread thread = new Thread(() -> {
    System.out.println("Processing...");
});

thread.start();
```

Suppose you need the result.

How do you return it?

```text
Thread
   ↓
No easy way to return a value
```

---

### Using CompletableFuture

```java
CompletableFuture<String> future =
        CompletableFuture.supplyAsync(() -> "Employee");

System.out.println(future.join());
```

Output

```
Employee
```

Here, getting the result is built in.

---

# Example 2: Three API Calls

Suppose you need

* Employee
* Salary
* Address

### Using Threads

```text
Thread1
Thread2
Thread3

Wait...
Join...
Collect Results...
Handle Exceptions...
```

Lots of manual work.

---

### Using CompletableFuture

```java
CompletableFuture<Employee> employee = ...
CompletableFuture<Salary> salary = ...
CompletableFuture<Address> address = ...

CompletableFuture.allOf(employee, salary, address).join();
```

Done.

---

# Example 3: WebClient + CompletableFuture

Suppose

* Call Employee Service
* Call Salary Service
* Call Department Service

You can combine all results.

```java
CompletableFuture<Employee> employee = ...
CompletableFuture<Salary> salary = ...
CompletableFuture<Department> department = ...

CompletableFuture.allOf(employee, salary, department)
        .join();
```

`WebClient` performs the HTTP calls, while `CompletableFuture` coordinates the asynchronous workflow.

---

# Why not just Thread?

| Thread                      | CompletableFuture                             |
| --------------------------- | --------------------------------------------- |
| Low-level API               | High-level async API                          |
| Manual thread management    | Uses thread pools (`Executor`)                |
| Difficult to return results | Returns values naturally                      |
| No chaining                 | Supports `thenApply()`, `thenCompose()`, etc. |
| Manual exception handling   | Built-in exception handling                   |
| Difficult to combine tasks  | `thenCombine()`, `allOf()`, `anyOf()`         |

---

# Why not just WebClient?

| WebClient                                   | CompletableFuture                                |
| ------------------------------------------- | ------------------------------------------------ |
| Only for HTTP calls                         | Works with any asynchronous task                 |
| Returns `Mono`/`Flux`                       | Returns `CompletableFuture`                      |
| Cannot coordinate all async logic by itself | Can combine, chain, and recover from async tasks |

# Interview Answer

**Q: We already have `Thread` and `WebClient`. Why do we need `CompletableFuture`?**

**Answer:**

* `Thread` is a low-level API for creating threads. It doesn't provide easy ways to return results, chain operations, combine tasks, or handle exceptions.
* `WebClient` is a non-blocking HTTP client. It is designed only for making asynchronous HTTP requests.
* `CompletableFuture` is a general-purpose asynchronous programming API. It lets you execute tasks asynchronously, chain dependent operations, combine independent tasks, handle exceptions, and coordinate multiple asynchronous operations in a clean, readable way.

**Easy Memory Trick**

```text
Thread
   ↓
Runs a task

WebClient
   ↓
Calls an API

CompletableFuture
   ↓
Manages the entire async workflow
   ↓
✔ Return Results
✔ Chain Tasks
✔ Combine Tasks
✔ Handle Exceptions
✔ Coordinate Async Operations
```

So, think of **`Thread` as the worker**, **`WebClient` as one type of asynchronous job**, and **`CompletableFuture` as the manager that coordinates all the asynchronous work.**
