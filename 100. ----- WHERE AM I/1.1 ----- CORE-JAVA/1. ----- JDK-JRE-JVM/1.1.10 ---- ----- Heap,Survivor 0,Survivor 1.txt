Excellent question. **Survivor Spaces (S0 and S1)** are one of the most frequently asked JVM interview topics. Let's understand them in detail with a real execution example.

---

# Java Heap

```text
                     Heap
                       │
      ┌────────────────┴────────────────┐
      │                                 │
 Young Generation                  Old Generation
      │
      ├── Eden
      ├── Survivor 0 (S0)
      └── Survivor 1 (S1)
```

The **Young Generation** has three parts:

* Eden
* Survivor 0 (From Space)
* Survivor 1 (To Space)

---

# Why do we need Survivor Spaces?

Imagine every object went directly from Eden to the Old Generation.

```text
Eden
 ↓
Old Generation
```

The Old Generation would fill up very quickly with short-lived objects.

Instead, the JVM gives objects a "second chance."

```text
Eden
 ↓
S0
 ↓
S1
 ↓
Old Generation
```

Only objects that survive several garbage collections are promoted to the Old Generation.

---

# Example

```java
public class Test {

    public static void main(String[] args) {

        Employee e1 = new Employee();
        Employee e2 = new Employee();
        Employee e3 = new Employee();
    }
}
```

Initially

```text
Young Generation

Eden

e1
e2
e3

S0 = Empty

S1 = Empty
```

---

# Minor Garbage Collection

Suppose after some time

```java
e1 = null;
e2 = null;
```

Only

```java
e3
```

is still referenced.

Before GC

```text
Eden

e1
e2
e3
```

During Minor GC

Garbage Collector checks:

```
e1 → unreachable
e2 → unreachable
e3 → reachable
```

Result

```
Delete e1
Delete e2
Move e3
```

Memory becomes

```text
Eden

Empty

S0

e3 (Age = 1)

S1

Empty
```

Notice

**Only the surviving object moved to Survivor Space.**

---

# Why Age = 1?

Every object has an internal **age** maintained by the JVM.

```
Created in Eden

Age = 0
```

After surviving one Minor GC

```
Age = 1
```

Survive another Minor GC

```
Age = 2
```

And so on.

---

# Next Minor GC

Create more objects

```java
Employee e4 = new Employee();
Employee e5 = new Employee();
```

Memory

```text
Eden

e4
e5

S0

e3 (Age=1)

S1

Empty
```

Suppose

```
e4 dies

e5 survives
```

GC happens.

Now

```
e3 survives again

Age becomes 2

e5 survives first time

Age becomes 1
```

The JVM copies them into the **other Survivor Space**.

```text
Eden

Empty

S0

Empty

S1

e3 (Age=2)

e5 (Age=1)
```

Notice

The JVM copied

```
S0

↓

S1
```

# Why Two Survivor Spaces?

Instead of moving objects inside the same memory,

the JVM copies live objects from one Survivor Space to the other.

```text
Cycle 1

Eden

↓

S0


Cycle 2

Eden

↓

S1


Cycle 3

Eden

↓

S0


Cycle 4

Eden

↓

S1
```

They keep swapping.

e3

# Why does the JVM do this?

Most objects in Java are **short-lived**.

Examples:

```java
String s = new String("Hello");
```

inside a method.

After the method returns,

```
s
```

dies.

If such objects were immediately promoted to the Old Generation:

* Old Generation would fill quickly.
* Full GCs would happen more often.
* Performance would decrease.

Survivor Spaces filter out short-lived objects and promote only long-lived ones.

# Interview Summary

```
New Object
    │
    ▼
 Eden (Age = 0)
    │
Minor GC
    │
    ▼
 Survivor 0 (Age = 1)
    │
Minor GC
    │
    ▼
 Survivor 1 (Age = 2)
    │
Minor GC
    │
    ▼
 Survivor 0 (Age = 3)
    │
    ...
    │
Age reaches threshold
    │
    ▼
 Old Generation
```

### Key interview points

* **Eden**: All new objects are created here.
* **Minor GC**: Runs when Eden fills up.
* **Surviving objects**: Copied to a Survivor Space and their age is incremented.
* **S0 and S1**: Only one is the **From Space** (source) and the other is the **To Space** (destination) during a GC. After GC, they swap roles.
* **Promotion**: Objects that survive enough Minor GCs (or when Survivor space cannot accommodate them) are moved to the Old Generation.
