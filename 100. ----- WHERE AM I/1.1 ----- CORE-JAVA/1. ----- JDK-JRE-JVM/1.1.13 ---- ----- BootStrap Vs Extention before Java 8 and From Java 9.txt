Almost, but there is an important difference between **Java 8** and **Java 9+**.

---

# Java 8

```text
               Bootstrap ClassLoader
                      │
                      │ Loads
                      ▼
                jre/lib/rt.jar
                jre/lib/resources.jar
                jre/lib/jsse.jar
                ...
```

The **Bootstrap ClassLoader** loads **core Java classes** from `rt.jar`.

Examples:

* java.lang.String
* java.lang.Object
* java.util.ArrayList
* java.io.File

---

```text
             Extension ClassLoader
                    │
                    │ Loads
                    ▼
           jre/lib/ext/*.jar
```

It loads extension libraries from:

```text
jre/lib/ext/
```

Examples:

* security providers
* Java Cryptography Extension (JCE)
* other optional extension JARs

---

# Java 9 and Later (Java 11, 17, 21...)

Java introduced the **Module System (Project Jigsaw)**.

There is **no `rt.jar`** and **no `jre/lib/ext` directory**.

Instead, classes are stored inside **modules**.

---

## Bootstrap ClassLoader

Loads **fundamental modules**.

Examples:

```text
java.base
java.logging
java.xml
java.sql
...
```

The most important module is:

```text
java.base
```

It contains

* java.lang
* java.util
* java.io
* java.net

Without `java.base`, the JVM cannot even start.

---

## Platform ClassLoader (formerly Extension ClassLoader)

In Java 9+, the **Extension ClassLoader was renamed to Platform ClassLoader**.

It loads **platform modules** that are **not loaded by Bootstrap**.

Examples:

```text
jdk.crypto.ec
jdk.compiler
jdk.management
jdk.jconsole
java.desktop
```

It **does not** load classes from `java.base`.

---

# Correct Hierarchy (Java 17/21)

```text
                 Bootstrap ClassLoader
                 ---------------------
                 Loads:
                 java.base
                 + other core modules
                        │
                        ▼
               Platform ClassLoader
               ---------------------
               Loads:
               Other platform/JDK modules
               (java.desktop, jdk.compiler,
                jdk.management, etc.)
                        │
                        ▼
             Application ClassLoader
             -----------------------
             Loads:
             Your application's
             classes and JARs
             from the classpath/module path
```

---

# Answer to your question

> **"Bootstrap and Extension class loader are both loads lib rt or module class files right?"**

**Java 8:**

* **Bootstrap** → Loads **`rt.jar`** (core libraries).
* **Extension** → Loads **`jre/lib/ext`** JARs.

They load **different locations**, not the same one.

**Java 9+:**

* **Bootstrap** → Loads **core modules**, especially `java.base`.
* **Platform (Extension)** → Loads **other JDK/platform modules**.

Again, they do **not** load the same modules.

---

## Interview Tip

Many interviewers still ask about the **Extension ClassLoader**, but since Java 9 it has been **replaced by the Platform ClassLoader**.

| Java Version | Bootstrap                                | Extension / Platform                 |
| ------------ | ---------------------------------------- | ------------------------------------ |
| **Java 8**   | Loads `rt.jar`                           | Loads `jre/lib/ext`                  |
| **Java 9+**  | Loads `java.base` and other core modules | Loads remaining platform/JDK modules |

So your diagram is **mostly correct for Java 9+**, but I'd change the Platform ClassLoader description from **"Loads ext libraries (jdk/lib, modules)"** to:

```text
Platform ClassLoader
----------------------------
Loads platform/JDK modules
(except java.base)
```

This wording is more accurate because the old **extension library (`jre/lib/ext`) mechanism no longer exists** in Java 9 and later.
