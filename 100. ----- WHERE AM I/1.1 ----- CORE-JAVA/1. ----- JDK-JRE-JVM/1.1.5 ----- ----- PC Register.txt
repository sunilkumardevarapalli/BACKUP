This is another excellent question. The answer is:

> **A PC Register is created once per thread, NOT per method call.**
>
> It is **updated for every bytecode instruction** that the JVM executes.

This is a very common interview question.

---

## 1. When is the PC Register created?

Suppose your program starts:

```java
public class Test {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
```

When the JVM creates the **main thread**, it also creates:

* ✅ Java Stack
* ✅ PC Register
* ✅ Native Method Stack

```text
Main Thread
     │
     ├── Java Stack
     ├── PC Register
     └── Native Method Stack
```

Only **one PC Register** exists for this thread.

---

## 2. Is a new PC Register created for every method?

**No.**

Consider:

```java
public class Test {

    static void m1() {
        System.out.println("M1");
    }

    public static void main(String[] args) {
        m1();
    }
}
```

Execution:

```text
Main Thread
     │
     ├── Java Stack
     │      main()
     │      m1()
     │
     └── PC Register   ← only ONE
```

When `m1()` is called:

* A new **stack frame** is pushed onto the Java Stack.
* **No new PC Register is created.**

---

## 3. What does the PC Register store?

It stores the **address (or index) of the current bytecode instruction** being executed.

For example:

```java
public static void main(String[] args) {

    int a = 10;

    int b = 20;

    int c = a + b;

    System.out.println(c);
}
```

The compiler generates bytecode similar to:

```text
0: bipush 10
2: istore_1
3: bipush 20
5: istore_2
6: iload_1
7: iload_2
8: iadd
9: istore_3
10: getstatic
13: iload_3
14: invokevirtual
17: return
```

The PC Register changes like this:

```text
Current PC

0  → executing bipush 10

↓

2  → executing istore_1

↓

3  → executing bipush 20

↓

5

↓

6

↓

7

↓

8

↓

9

↓

10

↓

13

↓

14

↓

17
```

So **the PC Register is updated for every bytecode instruction**, not just every source code line.

---

## 4. What happens when another method is called?

Example:

```java
public static void main(String[] args) {

    m1();

    System.out.println("Done");
}

static void m1() {

    System.out.println("Hello");
}
```

Execution:

```text
main()

↓

call m1()

↓

execute m1()

↓

return to main()

↓

execute println("Done")
```

The **same PC Register** is updated:

```text
PC

main instruction

↓

call m1()

↓

first instruction of m1()

↓

next instruction in m1()

↓

return

↓

next instruction in main()
```

No second PC Register is created.

---

## 5. What if there are two threads?

```java
Thread t1 = new Thread(...);
Thread t2 = new Thread(...);
```

Now:

```text
Thread-1
   │
   ├── Java Stack
   ├── PC Register
   └── Native Stack


Thread-2
   │
   ├── Java Stack
   ├── PC Register
   └── Native Stack
```

Each thread has **its own PC Register** because each thread executes independently.

---

## Summary

| Question                                    | Answer                                                               |
| ------------------------------------------- | -------------------------------------------------------------------- |
| Is a PC Register created for every method?  | ❌ No                                                                 |
| Is a PC Register created for every thread?  | ✅ Yes                                                                |
| Does it change during execution?            | ✅ Yes, for every bytecode instruction                                |
| What does it store?                         | The address/index of the current bytecode instruction being executed |
| How many PC Registers does one thread have? | Exactly one                                                          |

### Easy way to remember

* **Java Stack** = One per thread → contains many **stack frames** (one per active method call).
* **PC Register** = One per thread → keeps pointing to the **current bytecode instruction** being executed. It is continuously updated as execution progresses.
