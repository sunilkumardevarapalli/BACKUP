In Java collections, fail-fast and fail-safe describe how an iterator behaves when the collection is modified during iteration.

1. ArrayList → Fail-Fast

ArrayList iterator is fail-fast.

If one thread (or even the same thread) modifies the collection structurally while iterating, the iterator detects it.
It throws ConcurrentModificationException.
Detection is based on an internal modCount variable.
Example
import java.util.ArrayList;
import java.util.Iterator;

public class FailFastDemo {
    public static void main(String[] args) {
        ArrayList<String> list = new ArrayList<>();
        list.add("A");
        list.add("B");
        list.add("C");

        Iterator<String> itr = list.iterator();

        while (itr.hasNext()) {
            String value = itr.next();

            if ("B".equals(value)) {
                list.add("D"); // Structural modification
            }

            System.out.println(value);
        }
    }
}

Output
A
B
Exception in thread "main" java.util.ConcurrentModificationException

Why?

The iterator stores the expected modification count when created. If the collection's modCount changes unexpectedly, it throws ConcurrentModificationException.

2. CopyOnWriteArrayList → Fail-Safe

CopyOnWriteArrayList iterator is fail-safe (more accurately, snapshot-based).

A new copy of the array is created whenever a write operation occurs.
The iterator works on the snapshot that existed when the iterator was created.
No ConcurrentModificationException is thrown.
Example
import java.util.Iterator;
import java.util.concurrent.CopyOnWriteArrayList;

public class FailSafeDemo {
    public static void main(String[] args) {
        CopyOnWriteArrayList<String> list =
                new CopyOnWriteArrayList<>();

        list.add("A");
        list.add("B");
        list.add("C");

        Iterator<String> itr = list.iterator();

        while (itr.hasNext()) {
            String value = itr.next();

            if ("B".equals(value)) {
                list.add("D");
            }

            System.out.println(value);
        }

        System.out.println("Final List: " + list);
    }
}

Output
A
B
C
Final List: [A, B, C, D]


Notice:

Iterator does not see "D" because it iterates over the snapshot.
No exception occurs.
Comparison
Feature	ArrayList	CopyOnWriteArrayListIterator Type	Fail-Fast	Fail-Safe (Snapshot-based)
Concurrent Modification	Throws ConcurrentModificationException	No exception
Iterator Sees Latest Changes	No	No (sees snapshot)
Thread-Safe	No	Yes
Write Performance	Fast	Expensive (creates new copy)
Read Performance	Good	Excellent for read-heavy workloads
When to Use
Use ArrayList
Single-threaded applications.
Reads and writes happen frequently.
Best performance for normal operations.
Use CopyOnWriteArrayList
Multi-threaded applications.
Read operations are much more frequent than writes.
Examples: caching, listener lists, configuration data.
Interview One-Liner

ArrayList uses a fail-fast iterator and throws ConcurrentModificationException when modified during iteration, whereas CopyOnWriteArrayList uses a snapshot-based fail-safe iterator that works on a copied array and does not throw the exception.

------------------------

If you add an element using the iterator itself, the behavior differs:

ArrayList

Iterator does not support add().

Iterator<String> itr = list.iterator();
itr.add("D");   // Compilation error


Only ListIterator supports add().

ArrayList<String> list = new ArrayList<>();
list.add("A");
list.add("B");

ListIterator<String> it = list.listIterator();

while (it.hasNext()) {
    String val = it.next();

    if ("B".equals(val)) {
        it.add("D");   // Safe
    }
}

System.out.println(list);


Output:

[A, B, D]


No ConcurrentModificationException because the iterator updates its expected modification count.

CopyOnWriteArrayList

Its iterator is read-only.

CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
Iterator<String> itr = list.iterator();

itr.remove(); // UnsupportedOperationException


Similarly:

ListIterator<String> it = list.listIterator();
it.add("D");


throws:

java.lang.UnsupportedOperationException


because CopyOnWriteArrayList iterators operate on an immutable snapshot.

Summary
ArrayList
ListIterator.add() ✅ Supported
ListIterator.remove() ✅ Supported

CopyOnWriteArrayList
Iterator.remove() ❌ UnsupportedOperationException
ListIterator.add() ❌ UnsupportedOperationException
ListIterator.remove() ❌ UnsupportedOperationException

Interview Answer

In ArrayList, modifications through ListIterator (add, remove, set) are allowed and do not cause ConcurrentModificationException. In CopyOnWriteArrayList, iterators are snapshot-based and read-only, so add(), remove(), and set() through the iterator throw UnsupportedOperationException.
