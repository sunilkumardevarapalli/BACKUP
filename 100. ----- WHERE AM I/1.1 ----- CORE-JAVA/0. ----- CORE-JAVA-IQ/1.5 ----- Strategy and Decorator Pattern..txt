These are very common design pattern interview questions. Here's a simple explanation with real-time examples.

---

# 1. Strategy Pattern

## Definition

> **Strategy Pattern** allows you to **change an object's behavior (algorithm) at runtime** without modifying the object itself.

### Simple Formula

```text
One Task
     │
Multiple Algorithms
     │
Choose One at Runtime
```

---

## Real-Time Example

### Payment System

A customer can pay using:

* Credit Card
* UPI
* PayPal

The payment process changes, but the checkout process remains the same.

### Step 1: Strategy Interface

```java
interface PaymentStrategy {
    void pay(int amount);
}
```

---

### Step 2: Implementations

```java
class CreditCardPayment implements PaymentStrategy {

    public void pay(int amount) {
        System.out.println("Paid using Credit Card : " + amount);
    }
}
```

```java
class UpiPayment implements PaymentStrategy {

    public void pay(int amount) {
        System.out.println("Paid using UPI : " + amount);
    }
}
```

---

### Step 3: Context

```java
class ShoppingCart {

    private PaymentStrategy strategy;

    public ShoppingCart(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    public void checkout(int amount) {
        strategy.pay(amount);
    }
}
```

---

### Step 4: Client

```java
public class Main {

    public static void main(String[] args) {

        ShoppingCart cart =
                new ShoppingCart(new UpiPayment());

        cart.checkout(1000);
    }
}
```

Output

```text
Paid using UPI : 1000
```

---

## Diagram

```text
ShoppingCart
      │
      ▼
PaymentStrategy
      ▲
      │
-----------------------
│                     │
CreditCard        UPI
```

---

## When to use Strategy?

* Multiple payment methods
* Different tax calculations
* Different sorting algorithms
* Discount calculations
* Shipping methods

---

# 2. Decorator Pattern

## Definition

> **Decorator Pattern** adds **new functionality to an existing object dynamically without modifying its original class**.

### Simple Formula

```text
Existing Object
       │
Add Extra Features
       │
Without Changing Original Code
```

---

## Real-Time Example

### Coffee Shop

Base Coffee:

```text
Coffee
```

Customer wants:

* Milk
* Sugar

Instead of creating:

```
CoffeeWithMilk
CoffeeWithSugar
CoffeeWithMilkSugar
```

we decorate the coffee.

---

### Step 1: Component

```java
interface Coffee {
    String makeCoffee();
}
```

---

### Step 2: Basic Coffee

```java
class SimpleCoffee implements Coffee {

    public String makeCoffee() {
        return "Coffee";
    }
}
```

---

### Step 3: Decorator

```java
class MilkDecorator implements Coffee {

    private Coffee coffee;

    public MilkDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    public String makeCoffee() {
        return coffee.makeCoffee() + " + Milk";
    }
}
```

---

### Client

```java
public class Main {

    public static void main(String[] args) {

        Coffee coffee =
                new MilkDecorator(new SimpleCoffee());

        System.out.println(coffee.makeCoffee());
    }
}
```

Output

```text
Coffee + Milk
```

---

## Add Another Decorator

```java
class SugarDecorator implements Coffee {

    private Coffee coffee;

    public SugarDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    public String makeCoffee() {
        return coffee.makeCoffee() + " + Sugar";
    }
}
```

Usage

```java
Coffee coffee =
    new SugarDecorator(
        new MilkDecorator(
            new SimpleCoffee()));

System.out.println(coffee.makeCoffee());
```

Output

```text
Coffee + Milk + Sugar
```

---

## Diagram

```text
SimpleCoffee
      │
      ▼
MilkDecorator
      │
      ▼
SugarDecorator
```

Each decorator **adds behavior**.

---

# 3. Strategy vs Decorator

| Strategy Pattern                          | Decorator Pattern                   |
| ----------------------------------------- | ----------------------------------- |
| Changes **how** work is done (algorithm). | Adds **extra behavior/features**.   |
| One strategy is chosen at runtime.        | Multiple decorators can be stacked. |
| Focuses on behavior selection.            | Focuses on feature enhancement.     |
| Uses composition.                         | Uses composition.                   |

# Interview Trick

### Strategy

> "I want **different ways** to perform the same task."

Examples:

* Payment
* Sorting
* Discount
* Tax Calculation

---

### Decorator

> "I want to **add new features** to an existing object without changing its code."

Examples:

* Coffee + Milk
* Pizza + Cheese
* Logging around a service
* Compression + Encryption for files

# Best Interview Answer

### Strategy Pattern

> **Use the Strategy Pattern when you have multiple algorithms for the same task and want to choose one at runtime without changing the client code.**

### Decorator Pattern

> **Use the Decorator Pattern when you want to add new functionality to an existing object dynamically without modifying its original class.**

### Strategy vs Decorator

* **Strategy** → Changes the **algorithm/behavior**.
* **Decorator** → Adds **new functionality** to the existing object.
