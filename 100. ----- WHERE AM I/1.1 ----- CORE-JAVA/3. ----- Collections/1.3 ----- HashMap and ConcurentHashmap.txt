4. Can ConcurrentHashMap lock the entire map?
Answer

No.

Why?

Modern Java (Java 8+):

Does not lock the entire map.
Locks only the bucket (bin) being modified when needed.
Uses CAS (Compare-And-Swap) for many operations.
Allows other threads to access different buckets concurrently.


8. Which map performs better for read-heavy applications?
Single-threaded

Reason:

Lock-free reads.
Multiple threads can read simultaneously.

10. What happens internally during put() in ConcurrentHashMap?
Internally

put()

↓

Calculate hash

↓

Find bucket

↓

CAS attempt

↓

If needed, lock that bucket

↓

Insert or update node

↓

Unlock bucket

Only the affected bucket is locked if required.

11. What happens if two threads update the same key simultaneously?
Answer

Only one thread updates the key at a time.

Example:

Thread-1

↓

Locks bucket

↓

Updates value

↓

Unlocks

↓

Thread-2

↓

Locks same bucket

↓

Updates value

The updates are serialized for that bucket, preventing data corruption.
