# Which broker do they connect to?

Consumer1 owns:

```text
P0 -> Leader = Broker1

P3 -> Leader = Broker1
```

So Consumer1 polls Broker1.

```text
Consumer1
      |
      |
Broker1
```

---

Suppose instead the leaders were distributed like this:

```text
Broker1

Leader
P0
```

```text
Broker2

Leader
P1
P3
```

```text
Broker3

Leader
P2
P4
P5
```

Consumer1 still owns

```text
P0

P3
```

Now Consumer1 connects to **two brokers**:

```text
Consumer1

      |
      +-------> Broker1 (reads P0)

      |
      +-------> Broker2 (reads P3)
```

So a consumer reads from the **leader of each partition it owns**. It is **not tied to one broker**.

```text

P4 ---> Broker3 (Leader)

               Consumer Group

Consumer1 ---> P0, P3
                |    |
                |    +------ Broker2
                |
                +----------- Broker1

Consumer2 ---> P1, P4
                |    |
                |    +------ Broker3
                |
                +----------- Broker2

Consumer3 ---> P2, P5
                |    |
                |    +------ Broker1
                |
                +----------- Broker3
```

## Important interview point

A **consumer is assigned partitions**, **not brokers**.

For each assigned partition:

1. The consumer asks Kafka, **"Who is the leader for this partition?"**
2. Kafka returns the broker hosting that partition's leader.
3. The consumer polls **only that leader broker** for that partition.

So your statement:

> "Consumer1 has P0 and P3, so it will poll records only from P0 and P3, not from Consumer2 and Consumer3."

✅ **Correct.**

A slightly more precise wording is:

> **Consumer1 polls only its assigned partitions (P0 and P3). It never polls partitions assigned to Consumer2 (P1, P4) or Consumer3 (P2, P5).**
