This is the core of Kafka architecture. Let's understand **how multiple brokers form one cluster**, **how partitions are distributed**, and **how replicas are placed**.

---

# Step 1: Three Kafka Servers

Suppose you start three Kafka servers.

```text
Machine 1
----------
Broker 1
Port 9092

Machine 2
----------
Broker 2
Port 9093

Machine 3
----------
Broker 3
Port 9094
```

They become one Kafka cluster by connecting to the same **cluster metadata** (in modern Kafka, via the same KRaft controller quorum; in older versions, via ZooKeeper).

So Kafka sees:

```text
Kafka Cluster

+-----------+
| Broker 1  |
+-----------+

+-----------+
| Broker 2  |
+-----------+

+-----------+
| Broker 3  |
+-----------+
```

Each broker registers itself with the cluster using its unique `node.id`/`broker.id`, host, and port.

---

# Step 2: Create a Topic

Suppose you create:

```text
Topic : order-events

Partitions = 6

Replication Factor = 2
```

Meaning:

* 6 partitions
* Every partition has **1 Leader + 1 Replica**

---

# Step 3: Kafka Distributes Partitions

Kafka automatically spreads partitions across brokers.

```text
Broker 1              Broker 2              Broker 3
---------             ---------             ---------

P0 (Leader)           P2 (Leader)           P4 (Leader)

P1 (Replica)          P3 (Replica)          P5 (Replica)
```

This is only part of the picture because every partition also needs a replica.

---

# Step 4: Replicas

Since replication factor = 2

Every partition exists on **two brokers**.

```text
Partition 0

Leader
Broker1

Replica
Broker2
```

Partition 1

```text
Leader
Broker2

Replica
Broker3
```

Partition 2

```text
Leader
Broker3

Replica
Broker1
```

Kafka keeps balancing leaders and replicas so that one broker doesn't hold all leaders.

# Complete Distribution

```text
Broker 1

Leader
-------
P0
P3

Replica
--------
P2
P5
```

```text
Broker 2

Leader
-------
P1
P4

Replica
--------
P0
P3
```

```text
Broker 3

Leader
-------
P2
P5

Replica
--------
P1
P4
```

Notice:

* Every partition has one leader.
* Every partition has one replica.
* Replicas are always stored on different brokers.

# Producer Sends Data

Producer sends

```text
Order101
```

Partitioner decides

```text
Partition 3
```

Broker3?

No.

Kafka metadata says

```text
Partition 3

Leader = Broker1
Replica = Broker2
```

Producer writes only to the leader.

```text
Producer
    |
    |
Broker1 (Leader P3)
```

Broker1 writes to disk.

Immediately after

Broker2 copies it.

```text
Broker1

P3 Leader

Order101
      |
      |
Replication
      |
      V
Broker2

P3 Replica

Order101
```

Producer never writes directly to replicas.

---

# What Happens if Broker1 Crashes?

Suppose Broker1 dies.

Before crash

```text
Broker1

Leader P3
```

Broker2

```text
Replica P3
```

Kafka detects

```text
Broker1 is DOWN
```

Now

Broker2 becomes Leader.

```text
Broker2

Leader P3
```

Producer automatically receives updated metadata and starts sending new records for partition 3 to Broker2.

No data is lost (assuming the replica was fully caught up and your producer acknowledgment settings support durability).

---

# Why Spread Leaders?

Suppose all leaders are on Broker1.

```text
Broker1

Leader
P0
P1
P2
P3
P4
P5
```

All producer and consumer traffic goes through Broker1.

Broker2 and Broker3 are mostly idle.

Bad utilization.

Instead Kafka balances leaders.

```text
Broker1

Leader
P0
P3
```

```text
Broker2

Leader
P1
P4
```

```text
Broker3

Leader
P2
P5
```

Now all brokers share the work.

---

# Consumer Reads

Consumers never read from replicas (unless special features are configured).

They always read from the **leader**.

```text
Consumer

     |
     |
Leader Partition

Broker2
```

Replicas exist primarily for fault tolerance.

---

# Entire Flow

```text
                Kafka Cluster

          +------------------+
          |    Broker 1      |
          | L:P0   R:P2       |
          | L:P3   R:P5       |
          +------------------+
                 ^        |
                 |        |
          Replication     |
                 |        v
          +------------------+
          |    Broker 2      |
          | L:P1   R:P0       |
          | L:P4   R:P3       |
          +------------------+
                 ^        |
                 |        |
          Replication     |
                 |        v
          +------------------+
          |    Broker 3      |
          | L:P2   R:P1       |
          | L:P5   R:P4       |
          +------------------+

Producer
   |
   |----> Writes only to Leader

Consumer
   |
   |----> Reads only from Leader
```

### Summary

| Component                    | Responsibility                                                        |
| ---------------------------- | --------------------------------------------------------------------- |
| **Broker**                   | Stores partitions and replicas                                        |
| **Leader Partition**         | Handles all producer writes and consumer reads                        |
| **Replica Partition**        | Copies data from the leader for high availability                     |
| **Kafka Controller (KRaft)** | Assigns leaders and replicas and elects new leaders if a broker fails |
| **Producer**                 | Sends records only to the partition leader                            |
| **Consumer**                 | Reads records only from the partition leader                          |

**Interview tip:** If someone asks *"How are partitions and replicas distributed?"*, the answer is:

> Kafka's controller automatically assigns partition leaders and replicas across brokers to balance load and provide fault tolerance. Each partition has exactly one leader and one or more replicas (depending on the replication factor), and replicas are always placed on different brokers than their leader.
