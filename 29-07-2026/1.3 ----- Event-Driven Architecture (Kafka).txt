Event-Driven Architecture (EDA) with Kafka in Spring Boot Microservices

In a traditional microservices architecture, services communicate synchronously using REST APIs:

Order Service ---> Payment Service ---> Inventory Service


Problems:

Tight coupling
Increased latency
Service dependency failures
Scalability challenges

With Event-Driven Architecture, services communicate through events using Kafka.

                Kafka
                  |
      +-----------+-----------+
      |           |           |
      v           v           v
 Order MS   Payment MS   Inventory MS

Spring Boot Kafka Implementation
Order Service (Producer)
Dependency
<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>

Producer Configuration
spring:
  kafka:
    bootstrap-servers: localhost:9092

Event DTO
@Data
@AllArgsConstructor
@NoArgsConstructor
public class OrderCreatedEvent {

    private Long orderId;
    private Long userId;
    private Double amount;
}

Producer Service
@Service
@RequiredArgsConstructor
public class OrderProducer {

    private final KafkaTemplate<String, Object> kafkaTemplate;

    public void publishOrderCreatedEvent(
            OrderCreatedEvent event) {

        kafkaTemplate.send(
                "order-created",
                event);
    }
}

Order Controller
@RestController
@RequiredArgsConstructor
@RequestMapping("/orders")
public class OrderController {

    private final OrderProducer producer;

    @PostMapping
    public String createOrder() {

        OrderCreatedEvent event =
                new OrderCreatedEvent(
                        1001L,
                        101L,
                        500.0);

        producer.publishOrderCreatedEvent(event);

        return "Order Created";
    }
}

Payment Service (Consumer)
Configuration
spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: payment-group

Consumer
@Service
public class PaymentConsumer {

    @KafkaListener(
            topics = "order-created",
            groupId = "payment-group")
    public void consume(
            OrderCreatedEvent event) {

        System.out.println(
                "Payment Processing : "
                        + event.getOrderId());
    }
}

Inventory Service (Consumer)
@Service
public class InventoryConsumer {

    @KafkaListener(
            topics = "order-created",
            groupId = "inventory-group")
    public void consume(
            OrderCreatedEvent event) {

        System.out.println(
                "Inventory Updated : "
                        + event.getOrderId());
    }
}

JSON Serialization

Producer:

spring:

      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer


Consumer:

spring:
  kafka:
    consumer:
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      properties:
        spring.json.trusted.packages: "*"

Error Handling
Retry
@RetryableTopic(
    attempts = "3")
@KafkaListener(
        topics = "order-created")
public void consume(
        OrderCreatedEvent event) {

    process(event);
}

Idempotency

Kafka guarantees at-least-once delivery.

A message might be processed twice.

Bad:

if(processedEvents.contains(eventId)){

Interview Answer

Event-Driven Architecture is a microservices communication pattern where services communicate asynchronously by publishing and consuming events through a message broker like Kafka.

Benefits:

Loose coupling
Better scalability
Asynchronous processing
Fault tolerance
Independent deployments

Spring Boot Components:

KafkaTemplate → Producer
@KafkaListener → Consumer
Kafka Topics → Event channels
Consumer Groups → Load balancing
Dead Letter Topics → Failed messages
Retry + Idempotency → Reliability
Saga Pattern → Distributed transaction management

A common enterprise flow is:

Order Service
    -> OrderCreated Event
    -> Kafka
    -> Payment Service
    -> Inventory Service
    -> Notification Service


where services react to events rather than directly calling each other.
