6. Configure Gateway

The gateway does not need to know individual ports.

spring:
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://USER-SERVICE
          predicates:
            - Path=/users/**
			
lb:// means:Ask Eureka for USER-SERVICE instances

Eureka returns:


8081
8083
8084

Spring Cloud LoadBalancer picks one instance.

Request 1 -> 8081
Request 2 -> 8083
Request 3 -> 8084
Request 4 -> 8081


7. Running Multiple Instances Without Profiles

You can start the same jar multiple times:

java -jar user-service.jar --server.port=8081

java -jar user-service.jar --server.port=8083

java -jar user-service.jar --server.port=8084		

Common Eureka config:
spring:
  application:
    name: USER-SERVICE

eureka:
  client:
    service-url:
      defaultZone: http://localhost:8761/eureka/
	  
Note1: if we run below commands then we need 3 configuration files required in user-service 

	application.yml
	application-8081.yml
	application-8083.yml
	application-8084.yml

		java -jar user-service.jar --spring.profiles.active=8081

		java -jar user-service.jar --spring.profiles.active=8083

		java -jar user-service.jar --spring.profiles.active=8084


		application.yml

		spring:
		  application:
			name: USER-SERVICE

		eureka:
		  client:
			service-url:
			  defaultZone: http://localhost:8761/eureka/
			  
		application-8081.yml

		server:
		  port: 8081
		  
Note: if we run like below then only one application.yml file is fine

		java -jar user-service.jar --server.port=8081

		java -jar user-service.jar --server.port=8083

		java -jar user-service.jar --server.port=8084		  

		and override the port when starting:

		server:
		  port: 8081

		spring:
		  application:
			name: USER-SERVICE

		eureka:
		  client:
			service-url:
			  defaultZone: http://localhost:8761/eureka/


		server:
		  port: 8081

		spring:
		  application:
			name: USER-SERVICE

		eureka:
		  client:
			service-url:
			  defaultZone: http://localhost:8761/eureka/
			  
In this approach:

✅ Only one application.yml is needed.
 ✅ No application-8081.yml, application-8083.yml, application-8084.yml files.
 ✅ Eureka registers all three instances automatically.

For local development and interviews, the --server.port= approach is usually the simplest and most commonly used.

uri: http://localhost:8081 → only one instance, no service discovery.
uri: lb://USER-SERVICE → Eureka lookup + load balancing across 8081, 8083, 8084.
