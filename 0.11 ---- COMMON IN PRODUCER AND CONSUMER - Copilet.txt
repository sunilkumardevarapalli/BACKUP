Below is a Spring Boot + Apache Kafka Producer & Consumer Interview/Implementation Guide covering all 25 topics from both Producer and Consumer perspectives.

1. Idempotence
Purpose

Ensures a producer does not write duplicate messages due to retries.

Producer
spring.kafka.producer.properties.enable.idempotence=true
spring.kafka.producer.acks=all
spring.kafka.producer.properties.max.in.flight.requests.per.connection=5
spring.kafka.producer.retries=2147483647

How it works

Kafka assigns:

Producer ID (PID)
Sequence Number

Broker tracks sequence numbers and discards duplicates.

Benefits

✅ No duplicate writes during retries

✅ Required for Exactly Once Semantics (EOS)

Consumer

Consumer does not have idempotence.

To achieve idempotent processing:

if(processedEventExists(eventId)) {
    return;
}


Store processed IDs in:

DB
Redis
Cache
2. Acknowledgement (ACK)
Purpose

Controls durability and reliability.

Producer
ACK = 0
spring.kafka.producer.acks=0


Fastest but unsafe.

ACK = 1
spring.kafka.producer.acks=1


Leader acknowledges.

Good balance.

ACK = all (-1)
spring.kafka.producer.acks=all


Leader + ISR replicas acknowledge.

Most reliable.

Consumer

Consumer acknowledges offsets.

Auto Commit
spring.kafka.consumer.enable-auto-commit=true

Manual Ack
@KafkaListener(topics="orders")
public void consume(Order order,
                    Acknowledgment ack){

   process(order);
   ack.acknowledge();
}


Preferred in production.

4. Order Management (Message Ordering)
Producer

Ordering guaranteed only:

Same producer
Same partition

Use key:

kafkaTemplate.send(
     "orders",
     orderId,
     order
);


Same orderId → same partition.

Avoid:

max.in.flight.requests.per.connection > 5

Consumer

One partition = ordered messages.

Multiple partitions:

P0 → Consumer A
P1 → Consumer B
P2 → Consumer C


Ordering only inside partition.

12. Transactions (EOS)

Exactly Once Semantics

Producer
enable.idempotence=true
transactional.id=order-tx

kafkaTemplate.executeInTransaction(
   operations -> {
      operations.send("topic",msg);
      return true;
   });

Consumer
isolation.level=read_committed


Avoid reading aborted transactions.

20. Rebalancing Impact
Producer

Indirect impact.

During rebalance:

Consumer stops briefly
Lag may increase

Producer unaffected mostly.

Consumer

Major impact.

Triggers:

Consumer joins
Consumer leaves
Partition changes

Mitigation

Static Membership:

group.instance.id=consumer-1


Cooperative Rebalancing:

partition.assignment.strategy=
org.apache.kafka.clients.consumer.CooperativeStickyAssignor
